# 1. Project Overview

> 공공자전거 대여 시스템 — 소프트웨어 아키텍처 명세 (양식: `2026 AA 인증과제-보고서-양식-v4.2.docx`)
> 근거 자료: [AA_SharingBycle_1~6](../AA_SharingBycle_1.md)

## 1.1. Project Background

**배경 및 필요성**

공공자전거는 출퇴근·통학 등 단거리 이동과 대중교통 환승 구간(first/last mile)을 담당하는 친환경 교통수단이다. 지금까지는 지자체마다 시스템을 따로 구축해 운영해 왔다. 그래서 지역마다 회원·요금·앱이 달라 다른 지역에서 이용하기 불편하고, 시스템을 중복으로 구축·운영하는 비용이 들며, 대여소 장비 관리 수준도 지역마다 다르다. 현장 운영은 사람에 크게 의존한다. 자전거가 몰리거나 빈 대여소의 재배치, 파손 자전거 점검, 장비 고장 확인을 순찰과 민원으로 처리하고 있어 대응이 늦고 운영비가 많이 든다.

**시장 환경**

민간 공유 킥보드·전기자전거 서비스는 앱 하나로 즉시 대여하고 자동 결제하는 편리함을 앞세워 단거리 이동 수요를 빠르게 가져가고 있다. 공공자전거가 경쟁력을 유지하려면 다음이 필요하다.

- 민간 서비스 수준의 사용 편의성: 실시간 조회, 예약, QR 대여, 자동 결제
- 정류장형(거치대) 방식의 장점인 질서 있는 거치와 확실한 반납 확인을 살리는 것
- 무인 자동화를 통한 운영비 절감

**Project 범위**

| 구분 | 내용 |
|---|---|
| 장소/공간 | 전국 **5만 개 대여소**: 거치대, 인식 리더기, 잠금장치, 거치대 카메라, 키오스크 |
| 구축 대상 | **System Server** (이용자 앱·관리자 앱·결제 대행 시스템·대여소 장비와의 내/외부 인터페이스 포함) |
| 사용자 범위 | 앱 회원 이용자, 운영 관리자(관제), 재배치 기사·정비 담당자(간접 사용자) |
| 핵심 기능 | ① 대여소 조회 및 자전거 예약(15분 확보, 수수료 선결제) ② QR 스캔 대여 / 타 대여소 반납 가능 ③ 반납 확정 후 이용 요금 자동 결제 및 미결제자 대여 제한 ④ 카메라 기반 파손 점검 및 자동 대여 차단 ⑤ 장비 상태 수집·고장 알림, 원격 잠금 제어 ⑥ 재배치 필요 대여소 추천 및 '재배치 중' 관리 |
| 가치/기대효과 | 이용자: 언제 어디서나 확실하고 빠른 대여·반납, 정확한 요금 / 운영기관: 무인 자동화로 운영비 절감, 서비스 품질 표준화, 수요 증가에 대한 대응력 확보 |

## 1.2. Stakeholder List

| Stakeholder | Description |
|---|---|
| **자전거 이용자** (앱 회원) | **배경**: 출퇴근·통학·여가 목적으로 공공자전거를 이용하는 시민이며, 대중교통과 연계해 단거리를 이동한다.<br>**역할**: 앱으로 대여소를 조회·예약하고, QR로 대여하며, 아무 대여소에나 반납하고, 등록한 신용카드로 요금을 낸다.<br>**애로사항**: 대여소에 도착했는데 자전거가 없거나 반납할 빈 거치대가 없어 헛걸음한다. 출퇴근 시간에 대여·반납이 지연되면 이동 일정에 차질이 생긴다. 반납했는데 처리가 안 되거나 요금이 중복으로 청구될까 불안하다. 파손된 자전거를 빌리면 안전이 위협받는다. |
| **운영 관리자** (공공자전거 운영기관 관제센터) | **배경**: 공공자전거 서비스를 위탁받아 운영하는 기관에 소속되어 있으며, 소속 기관의 목적은 안정적이고 효율적인 서비스 제공이다.<br>**역할**: 전국 대여소의 거치 현황을 감시하고, 재배치 작업을 지시하며, 장비 고장에 대응하고, 잠금장치를 원격으로 제어한다.<br>**애로사항**: 5만 개 대여소의 쏠림 상황을 사람이 파악하기 어려워 재배치가 늦다. 장비 고장을 민원이 들어온 뒤에야 알게 된다. 재배치 차량이 옮기는 자전거와 실제 대여를 구분하기 어려워 운영 기록이 꼬인다. |
| **재배치 기사** | **배경**: 운영기관 또는 협력업체 소속의 현장 인력이다.<br>**역할**: 관리자가 전화 등으로 지시하면 자전거를 수거해 부족한 대여소로 옮겨 거치한다.<br>**애로사항**: 지시가 늦게 오거나 현장 상황과 맞지 않아 헛걸음한다. 옮긴 자전거가 대여로 처리되어 요금 문제가 생길 수 있다. |
| **정비 담당자** | **배경**: 운영기관의 정비팀 소속이며, 자전거 안전 상태를 책임진다.<br>**역할**: 정비가 필요한 자전거를 회수·수리하고, 수리를 마치면 다시 운영에 투입한다.<br>**애로사항**: 순회 점검과 민원에 의존하다 보니 파손 자전거를 늦게 발견하고, 그사이 다른 이용자가 대여하는 안전 사고 위험이 있다. 점검할 대상을 찾는 데 드는 인력 부담이 크다. |
| **사업 발주 담당자** (중앙 공공기관 / 지자체 교통정책 부서) | **배경**: 공공자전거 사업의 예산을 편성하고 사업을 기획·도입하는 공공 조직이며, 목적은 친환경 교통 활성화와 시민 편익 증진이다.<br>**역할**: 사업을 기획·발주하고, 시스템을 도입·검수하며, 운영 성과를 평가하고, 노후 시스템을 교체·폐기한다.<br>**애로사항**: 지자체별 중복 구축으로 예산이 낭비된다. 운영 적자와 요금 미수금이 쌓인다. 서비스 장애나 개인정보 사고가 나면 기관이 비판을 받는다. 이용 수요가 늘 때마다 시스템을 다시 구축해야 하는 부담이 있다. |
| **개인정보보호 책임자** (운영기관 CPO) | **배경**: 운영기관의 정보보호 조직에 소속되어 있으며, 관련 법규 준수를 책임진다.<br>**역할**: 회원 개인정보와 신용카드 정보, 위치·이용 이력의 처리 방침을 수립하고 점검한다.<br>**애로사항**: 수백만 회원의 결제·위치 정보를 다루므로 한 번의 유출도 법적 제재와 신뢰 하락으로 이어진다. 정기적인 보안 인증 심사에 대응하는 부담이 있다. |
| **결제 대행사 연동 담당자** (PG사) | **배경**: 신용카드 결제를 대행하는 외부 사업자 소속이다.<br>**역할**: 예약 수수료 선결제, 이용 요금 자동 결제, 결제 실패 통보, 정산 대사를 수행한다.<br>**애로사항**: 같은 거래에 승인이 중복으로 요청되거나 취소 요청이 누락되어 정산 불일치와 고객 민원이 생긴다. |
| **대여소 장비 공급업체** (리더기·잠금장치·카메라·키오스크 제조사) | **배경**: 대여소 장비를 제조·납품하고 설치하는 업체다.<br>**역할**: 장비를 공급·설치하고, 펌웨어를 관리하며, 하자를 보수한다.<br>**애로사항**: 장비 모델이 바뀌거나 공급사가 늘어날 때마다 서버 연동을 새로 개발·시험해야 해서 납품 기간이 길어진다. 현장 고장 원인이 장비 문제인지 통신 문제인지 구분하기 어렵다. |
| **시스템 개발사** (SI 사업 PM·아키텍트) | **배경**: System Server 구축을 수주한 개발 조직이다.<br>**역할**: 시스템을 분석·설계·구현·시험하고 검수를 받는다.<br>**애로사항**: 연동 대상(앱, PG, 다종 장비)이 많고 요구사항이 자주 바뀌어 일정·비용이 초과될 위험이 있다. 전국 규모의 부하를 시험하기 어렵다. |
| **시스템 운영·유지보수 엔지니어** | **배경**: 운영기관 IT팀 또는 유지보수 계약 업체 소속이다.<br>**역할**: 서버를 운영·감시하고, 장애에 대응하며, 기능 개선과 배포를 맡는다.<br>**애로사항**: 연중 24시간 서비스라 점검을 위해 시스템을 멈출 시간이 없다. 장애가 나면 전국 서비스가 영향을 받는다. 변경 하나가 넓은 범위에 영향을 줘서 유지보수 비용이 커진다. |

## 1.3. Business Goal List

| Stakeholder | ID | Business Goal Statement | I |
|---|---|---|---|
| 자전거 이용자 | BG-01 | 대여소에서 대여·반납이 지연되지 않도록 하여, **대여·반납 소요시간에 대한 이용자 만족도를 4.5점/5점 이상**으로 높인다. | 상 |
| | BG-02 | 원하는 대여소에서 확실하게 자전거를 이용할 수 있도록, **예약 후 대여 실패율 1% 미만**, **자전거나 빈 거치대가 없어 헛걸음했다는 민원을 현행 대비 50% 감소**시킨다. | 중 |
| | BG-03 | 요금을 믿고 쓸 수 있도록 **요금 중복 청구·누락 관련 민원을 0건**으로 유지한다. | 상 |
| 운영 관리자 | BG-04 | 대여소 간 자전거 쏠림을 줄여 **대여 불가(자전거 0대) 또는 반납 불가(빈 거치대 0개) 상태인 대여소-시간 비율을 5% 이하**로 낮춘다. | 중 |
| | BG-05 | 대여소 장비 고장으로 인한 서비스 공백을 줄이기 위해 **고장 발생부터 관리자 인지까지 평균 5분 이내**, **민원으로 처음 알게 되는 고장 비율 10% 이하**를 달성한다. | 상 |
| 재배치 기사 | BG-06 | 재배치 작업이 이용 기록·요금과 섞이지 않도록 **재배치로 인한 요금 오처리·기록 오류를 0건**으로 유지한다. | 중 |
| 정비 담당자 | BG-07 | 파손 자전거가 이용자에게 대여되지 않도록 하여 **파손 자전거 대여로 인한 안전 사고 0건**을 달성하고, **순회 점검 인력을 현행 대비 30% 절감**한다. | 상 |
| 사업 발주 담당자 | BG-08 | 연중무휴 공공 서비스로서 신뢰를 확보하기 위해 **서비스 가용률 99.9% 이상(365일 24시간)**을 달성한다. | 상 |
| | BG-09 | 운영 수지를 개선하기 위해 **이용 요금 미수율을 1% 이하**로 낮춘다. | 중 |
| | BG-10 | 수요 증가에 대비해 **대여소·회원 수가 2배로 늘어도 시스템을 다시 구축하지 않고** 서비스할 수 있게 한다. | 중 |
| 개인정보보호 책임자 | BG-11 | **개인정보·결제정보 유출 사고 0건**을 유지하고 **개인정보보호 관련 보안 인증을 획득·유지**한다. | 상 |
| 결제 대행사 연동 담당자 | BG-12 | **결제 승인·취소 정산 불일치 건수를 월 0.01% 이하**로 유지한다. | 하 |
| 대여소 장비 공급업체 | BG-13 | **신규 장비 모델의 서버 연동 기간을 2주 이내**로 단축해 납품 기간을 줄인다. | 하 |
| 시스템 개발사 | BG-14 | 다수 연동 대상과 잦은 요구사항 변경에도 **계획한 일정·예산 대비 초과율을 10% 이내**로 유지한다. | 중 |
| 시스템 운영·유지보수 엔지니어 | BG-15 | **기능 배포·점검을 서비스 중단 없이(계획 정지 0시간)** 수행하고, **장애 원인 파악 시간을 평균 30분 이내**로 줄인다. | 중 |

\* I(Importance): 상 / 중 / 하로 구분
\* BG 간 충돌 시 우선순위 근거: 중요도 상 > 중 > 하 순으로 적용하며, '상' 안에서는 안전(BG-07)·요금 정확성(BG-03)·보안(BG-11)을 가용성(BG-08)·신속성(BG-01)·고장 인지(BG-05)보다 우선한다.
